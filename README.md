# نظام تقييد الحسابات - توثيق التسليم

## نظرة عامة

نظام تقييد حسابات متكامل بمستوى المنصات الكبرى: عند تقييد مستخدم يوجه تلقائياً إلى صفحة تقييد بعنوان طويل عشوائي يعرض بطاقة حسابه كاملة (الصورة الشخصية، الاسم، اسم المستخدم، تاريخ التقييد، السبب، الحالة، مرجع القضية) مع مسار طعن بخمس خطوات، ومبني كحزمة تتكون من إضافة خادم واحدة وواجهة أمامية مبنية بـ Vue مقسمة إلى عشرات الملفات.

الحزمة: `restriction-routes.js` تُركب على خادم Express الرئيسي بدون أي تعديل عليه، و `restriction-vue/dist` بناء الواجهة الجاهز.

## آلية عمل الروابط الطويلة

عندما يحاول مستخدم مقيد فتح أي صفحة محمية:

1. الوسيط `requireNotRestricted` يكتشف التقييد من قاعدة البيانات.
2. يولد توكناً عشوائياً بطول 178 خانة (أرقام وحروف) عبر `crypto` مع خلط فيشر-ييتس.
3. التوكن ثابت لكل مستخدم: تكرار التوليد لنفس المستخدم ضمن الصلاحية يعيد نفس التوكن بدل إغراق المتصفح بتوكنات جديدة.
4. يخزن التوكن في خريطة داخلية مرتبطة بمعرف المستخدم مع صلاحية 6 ساعات (قابلة للضبط عبر `RESTRICTION_TOKEN_TTL_MS`).
5. يعيد توجيه المتصفح نحو `/restriction.html/<token>` مثلاً:

```
/restriction.html/9byvgdr4167yz812kq85r07zz8h23vnb5hc1edcgnzp8gbckq50k8e5aw81jmsg5rxqu39c9dp7x86dv5h8t9y2wsjt84q6bqfe7m5k1n0rdt0kz4r4h2g9h0a871vpc1b0ngwm6437d1q9zm0i1k2o0i
```

6. كل توكن يولد مرجع قضية ثابت بالشكل `RV-XXXXXXXXXX` مشتق من SHA-256 للتوكن، يظهر في الواجهة ويُسجل في سجل التدقيق.

## الصمود أمام الحراس الوسطاء

النسخة 2.2 تعتمد مبدأ القائمة البيضاء الصارم: الواجهة لا تطلب عبر الشبكة سوى مسارين قديمة مضمونة المرور عند أي حارس — `GET /api/restriction/status` ونقاط الطعن `appeal/*` — إضافة إلى الملفات الثابتة. القياس والترجمة عن بعد والإعدادات عن بعد ونقطة heartbeat الشبكية أُزيلت جميعها من المتصفح، فلا يمكن أن يظهر أي طلب أحمر في أدوات المطور مهما كان الحارس صارماً.

الواجهة تعمل مع جيلين من الخادم:

1. مع الخادم الجديد: حقن `window.__RESTRICTION_BOOT__` في الصفحة يحمل التوكن والملف الشخصي والإعدادات فتعمل الواجهة بصفر طلبات API، و`status` يغرس التوكن والمرجع والملف و `cfg`، والتوكن ثابت لكل مستخدم بطول 178 خانة، وترويسة `X-Restriction-Engine` تثبت النشر.
2. مع الخادم القديم الموجود أصلاً: الواجهة تبني بطاقة الحساب كاملة من الحقول القديمة في `status` (username و displayName و avatar و reason و restrictedAt و appealStatus) وتعرض كل خطوات الطعن بنفس المستوى، دون الرابط الطويل حتى يُنشر الملف الجديد.

النبضة الدورية تستعمل `status` نفسه كل 25 ثانية، فتكشف رفع التقييد لحظة وقوعه وتبدل الشاشة إلى حالة الاستعادة مع زر العودة للرئيسية بدل شاشة منتهية الصلاحية المحيرة.

ترتيب تسوية الجلسة: الحقن أولاً، ثم `status` بالصيغة الجديدة، ثم `status` بالصيغة القديمة، ثم نسخة مخبأة محلياً لست ساعات، ثم شاشة الاستعادة إن كان الحساب حراً، وأخيراً شاشة انتهاء الصلاحية عند غياب الجلسة.

## المسارات الجديدة في الإضافة

| المسار | الوصف |
|---|---|
| `GET /restriction.html` و `GET /restriction.html/:token` | تقديم واجهة التقييد مع ترويسات أمان وحقن بيانات الإقلاع |
| `GET /restriction-assets/*` | الملفات الثابتة للبناء مع تخزين مؤقت طويل و immutable |
| `GET /api/restriction/session/:token` | بيانات الحساب المقيد المرتبطة بالتوكن |
| `POST /api/restriction/token` | توليد توكن جديد من جلسة مستخدم مقيد مع الملف الشخصي |
| `GET /api/restriction/bootstrap` | إعدادات الواجهة: العلامة، مفتاح captcha، الميزات، الروابط، توقيت الخادم |
| `GET /api/restriction/i18n/:locale` | قاموس ترجمة الواجهة من الخادم (ar و en) |
| `GET /api/restriction/heartbeat` | نبضة صحة مع توقيت الخادم و uptime |
| `POST /api/restriction/telemetry` | استقبال أحداث القياس من الواجهة مع تحديد معدل وتسجيل الأحداث المهمة في auditLog |

مسار `GET /api/restriction/status` أصبح يغرس عند وجود تقييد: `token` و `url` و `reference` و كائن `profile` كامل بجانب الحقول القديمة نفسها، فلا يتضرر أي مستهلك قديم.

كل مسارات الإصدار السابق (appeal بخطواته الأربع و admin و logout) محفوظة بنفس السلوك.

## حقن الاعتماديات

الإضافة تقبل في `deps` اختيارياً:

- `emailService`: خدمة بريد بديلة (الافتراضي `./email-service` مع تراجع صامت).
- `hcaptchaVerifier`: دالة تحقق بديلة من hCaptcha (الافتراضي طلب مباشر إلى siteverify).
- `distDir`: مسار بديل لمجلد البناء (الافتراضي `restriction-vue/dist` بجانب الإضافة أو `RESTRICTION_DIST_DIR`).

## متغيرات البيئة

| المتغير | الوظيفة |
|---|---|
| `RESTRICTION_ADMIN_SECRET` | سر لوحة الأدمن (إلزامي) |
| `HCAPTCHA_SECRET_KEY` | سر hCaptcha للتحقق من الطعون |
| `HCAPTCHA_SITE_KEY` | مفتاح الموقع الذي يوزع على الواجهة |
| `RESTRICTION_TOKEN_TTL_MS` | صلاحية توكن التقييد بالمللي ثانية (الافتراضي 21600000) |
| `RESTRICTION_BRAND_NAME` / `RESTRICTION_BRAND_LOGO` | اسم العلامة وشعارها في الواجهة |
| `RESTRICTION_HEARTBEAT_MS` | فترة النبضة (الافتراضي 25000) |
| `RESTRICTION_TELEMETRY_ENABLED` | صفر لتعطيل القياس |
| `RESTRICTION_LINK_*` | روابط التذييل: HELP TERMS PRIVACY ABOUT LOGIN HOME |

## ملاحظات التركيب على الخادم الرئيسي

1. استبدل الملف القديم `restriction-routes.js` بالجديد، واستبدل مجلد `restriction-vue/dist` كاملاً، ثم أعد تشغيل الخادم. لا يحتاج الأمر أي تعديل داخل ملف الخادم الرئيسي.
2. ركب الإضافة قبل `express.static` إن أمكن لضمان أن مسار `/restriction.html` يخدم الواجهة الجديدة، واحذف أو أعد تسمية ملف `restriction.html` القديم من مجلد الملفات الثابتة.
3. لا تغيير مطلوب في قاعدة البيانات: نفس الأعمدة السابقة تكفي، وعمودا `display_name` و `avatar` يقرآن إن وجدا مع تراجع تلقائي آمن.
4. الواجهة القديمة `account-center.html` نُظفت من كل التعليقات والرموز التعبيرية مع بقاء وظائفها كما هي.

## بنية الواجهة

البناء النهائي 62 ملفاً (56 جافاسكربت و5 أوراق أنماط وindex.html) موزعة بتقسيم يدوي لكل خدمة ومخزن ومكوّن وقاموس لغة، فتظهر في أدوات المطور عشرات الطلبات كما في التطبيقات الكبيرة، مع base ثابت على `/restriction-assets/` وترويسات immutable لمدة أسبوع.

## أداة التشخيص الخارجية

الملف `guard-probe.js` فاحص صندوق أسود بلا مكتبات يعمل بـ Node 18 وما فوق:

```
node guard-probe.js https://2-mmdv.onrender.com
node guard-probe.js https://2-mmdv.onrender.com --cookie "sessionToken=XXXX"
```

يختبر عشر نقاط وموقعين مجهولين ويقرأ الترويسات وأشكال JSON، ثم يطبع حكماً نهائياً يجيب عن ثلاثة أسئلة: هل محرك التقييد الجديد منشور (ترويسة X-Restriction-Engine ونسخته)، هل صيغة status قديمة أم جديدة، وهل وسيط الحظر يضرب هذا المتصفح (تمرير كوكي المتصفح المشكوك فيه يكشف الرد 403 برسالة قسم الاستدلال مقابل 404 العادي للمتصفح النظيف).

المكدس: Vue 3 و Pinia و Tailwind و Vite، خط Cairo، أيقونات Font Awesome من cdnjs، اتجاه RTL افتراضي مع حزمة en كاملة، وتصميم داكن بطابع Instagram.

## التشغيل التجريبي المحلي

مجلد `demo` يحوي خادماً تجريبياً كاملاً ببيانات وهمية في الذاكرة:

```
cd demo && npm install && node server.js
```

ثم افتح المنفذ 4800 واضغط أزرار المحاكاة لترى التوجيه الطويل وبطاقة الحساب ومسار الطعن كاملاً حتى حالة pending.

## فحوص الجودة المنفذة

- فحص آلي على كل الملفات (130 ملفاً) يؤكد خلوها من التعليقات والرموز التعبيرية بالكامل، بما فيها مخرجات البناء النهائي.
- `node --check` على الإضافة وخادم العرض.
- اختبار تكامل كامل: التوجيه مع توكن ثابت بطول 178 خانة، غرس status، حقن الصفحة وصحة JSON المحقون، الصمود أمام توكنات منتهية، تسلسل الطعن كاملاً من captcha حتى pending، وتقديم الأصول مع ترويسات التخزين الصحيحة.
