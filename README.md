# نظام تقييد الحسابات - توثيق التسليم

## نظرة عامة

هذا التسليم يعيد بناء نظام تقييد الحسابات بالكامل بمستوى احترافي عال:

1. الإضافة `restriction-routes.js` أصبحت توجه المستخدم المقيد إلى رابط طويل عشوائي فريد بدل المسار الثابت `/restriction.html`.
2. صفحة التقييد أعيد بناؤها كتطبيق Vue احترافي يعرض بطاقة الحساب المقيد كاملة: الصورة الشخصية، الاسم المعروض، اسم المستخدم، تاريخ التقييد، سبب التقييد، حالة الاعتراض، ومرجع القضية.
3. الواجهة مبنية بتقسيم دقيق للملفات (61 ملفاً في البناء النهائي) وتنفذ عشرات طلبات الشبكة المتدرجة كالتطبيقات الكبيرة.
4. لا توجد أي تعليقات أو رموز تعبيرية (إيموجي) في أي ملف من ملفات التسليم.

## آلية عمل الروابط الطويلة

عندما يحاول مستخدم مقيد فتح أي صفحة محمية:

1. الوسيط `requireNotRestricted` يكتشف التقييد من قاعدة البيانات.
2. يولد توكناً عشوائياً بطول 178 خانة (أرقام وحروف) عبر `crypto` مع خلط فيشر-ييتس.
3. يخزن التوكن في خريطة داخلية مرتبطة بمعرف المستخدم مع صلاحية 6 ساعات (قابلة للضبط عبر `RESTRICTION_TOKEN_TTL_MS`).
4. يعيد توجيه المتصفح نحو `/restriction.html/<token>` مثلاً:

```
/restriction.html/9byvgdr4167yz812kq85r07zz8h23vnb5hc1edcgnzp8gbckq50k8e5aw81jmsg5rxqu39c9dp7x86dv5h8t9y2wsjt84q6bqfe7m5k1n0rdt0kz4r4h2g9h0a871vpc1b0ngwm6437d1q9zm0i1k2o0i
```

5. الصفحة تقرأ التوكن من المسار وتطلب `GET /api/restriction/session/<token>` لجلب بيانات الحساب المقيد وعرضها.
6. كل توكن يولد مرجع قضية ثابت بالشكل `RV-XXXXXXXXXX` مشتق من SHA-256 للتوكن، يظهر في الواجهة ويُسجل في سجل التدقيق.

إذا انتهت صلاحية التوكن أو ضاع، الواجهة تحاول تلقائياً توليد توكن جديد عبر `POST /api/restriction/token` باستخدام جلسة المستخدم، وتستبدل الرابط عبر `history.replaceState` بدون إعادة تحميل. إن لم يكن هناك جلسة تظهر شاشة "انتهت صلاحية الجلسة" مع زر تسجيل الدخول.

## المسارات الجديدة في الإضافة

| المسار | الوصف |
|---|---|
| `GET /restriction.html` و `GET /restriction.html/:token` | تقديم واجهة التقييد المبنية مع ترويسات أمان |
| `GET /restriction-assets/*` | الملفات الثابتة للبناء مع تخزين مؤقت طويل و immutable |
| `GET /api/restriction/session/:token` | بيانات الحساب المقيد المرتبطة بالتوكن |
| `POST /api/restriction/token` | توليد توكن جديد من جلسة مستخدم مقيد |
| `GET /api/restriction/bootstrap` | إعدادات الواجهة: العلامة، مفتاح captcha، الميزات، الروابط، توقيت الخادم |
| `GET /api/restriction/i18n/:locale` | قاموس ترجمة الواجهة من الخادم (ar و en) |
| `GET /api/restriction/heartbeat` | نبضة صحة مع توقيت الخادم و uptime |
| `POST /api/restriction/telemetry` | استقبال أحداث القياس من الواجهة مع تحديد معدل وتسجيل الأحداث المهمة في auditLog |

كل مسارات الإصدار السابق (status و appeal بخطواته الأربع و admin و logout) محفوظة بنفس السلوك.

## حقن الاعتماديات

الإضافة تقبل الآن في `deps` اختيارياً:

- `emailService`: خدمة بريد بديلة (الافتراضي `./email-service` مع تراجع صامت).
- `hcaptchaVerifier`: دالة تحقق بديلة من hCaptcha (الافتراضي طلب مباشر إلى siteverify).
- `distDir`: مسار بديل لمجلد البناء (الافتراضي `restriction-vue/dist` بجانب الإضافة أو `RESTRICTION_DIST_DIR`).

## متغيرات البيئة

| المتغير | الوظيفة |
|---|---|
| `RESTRICTION_ADMIN_SECRET` | سر لوحة الأدمن (إلزامي) |
| `HCAPTCHA_SECRET_KEY` | سر hCaptcha للتحقق من الطعون |
| `HCAPTCHA_SITE_KEY` | مفتاح الموقع الذي يوزع على الواجهة |
| `RESTRICTION_TOKEN_TTL_MS` | صلاحية توكن التقييد بالمللي ثانية (الافتراضي 21600000) |
| `RESTRICTION_BRAND_NAME` / `RESTRICTION_BRAND_LOGO` | اسم العلامة وشعارها في الواجهة |
| `RESTRICTION_HEARTBEAT_MS` | فترة النبضة (الافتراضي 25000) |
| `RESTRICTION_TELEMETRY_ENABLED` | صفر لتعطيل القياس |
| `RESTRICTION_LINK_*` | روابط التذييل: HELP TERMS PRIVACY ABOUT LOGIN HOME |

## ملاحظات التركيب على الخادم الرئيسي

1. ركب الإضافة قبل `express.static` لضمان أن مسار `/restriction.html` يخدم الواجهة الجديدة.
2. احذف أو أعد تسمية ملف `restriction.html` القديم من مجلد الملفات الثابتة حتى لا يحجب المسار الجديد. التوجيهات التلقائية تذهب دائماً إلى `/restriction.html/<token>` وهي مملوكة للإضافة بالكامل.
3. لا تغيير مطلوب في قاعدة البيانات: نفس الأعمدة السابقة تكفي، وعمودا `display_name` و `avatar` يقرآن إن وجدا مع تراجع تلقائي آمن.
4. الواجهة القديمة `account-center.html` نُظفت من كل التعليقات والرموز التعبيرية مع بقاء وظائفها كما هي.

## بنية الواجهة

المشروع في `restriction-vue/` مبني بـ Vue 3 و Pinia و Tailwind و Vite 6:

- 21 خدمة في `src/services` تشمل http مع تتبع طلبات، telemetry مع دفعات و beacon، قياس أداء (navigation و paint و LCP و CLS)، بصمة جهاز غير تطفلية، معايرة توقيت الخادم، heartbeat، وجلسة التقييد.
- 4 مخازن Pinia: session و appeal و i18n و ui.
- 25 مكوناً كلها محملة كسولاً (defineAsyncComponent) عدا قشرة الإقلاع.
- الترجمة تجلب من الخادم أولاً ثم تدمج فوق نسخة محلية احتياطية، مع دعم RTL و LTR وتبديل تلقائي للاتجاه.
- تحميل استباقي متدرج للوحدات عبر requestIdleCallback (network warmup) كما في التطبيقات الكبيرة.

البناء النهائي في `restriction-vue/dist`:

| النوع | العدد |
|---|---|
| إجمالي الملفات | 61 |
| ملفات JavaScript | 55 |
| ملفات CSS | 5 |
| index.html | 1 |

أثناء تشغيل الصفحة سترى في أدوات المطور (F12) عشرات الطلبات: وثيقة الصفحة، ملفات JS و CSS المجزأة، طلبات bootstrap و i18n و session و status و heartbeat الدورية و telemetry و تحميل الوحدات الاستباقي، إضافة إلى موارد الخطوط والأيقونات الخارجية.

## التشغيل التجريبي المحلي

مجلد `demo/` يحتوي خادماً تجريبياً يركب الإضافة الحقيقية مع قاعدة بيانات وهمية في الذاكرة لمستخدم مقيد `@hassani.dev`:

```
cd demo
npm install
npm start
```

ثم افتح المنفذ 4800 وستجد أزراراً لمحاكاة دخول مستخدم مقيد، توليد رابط تقييد مباشر، عرض آخر بريد OTP، وإعادة الضبط. مفتاح hCaptcha في التجريب هو مفتاح الاختبار الرسمي لذا يجتاز التحقق دائماً، والبريد يلتقط في الذاكرة ويعرض من `/demo/mail`.

## فحوص الجودة المنفذة

- فحص آلي على 128 ملفاً: لا تعليقات (سطرية أو كتلية أو HTML) ولا رموز تعبيرية في أي ملف مصدري أو مبني، بما في ذلك إزالة بنرات تراخيص المكتبات من ملفات البناء عبر `legalComments: none`.
- اختبار متكامل للتدفق: توجيه الوسيط، جلب الجلسة، تجديد التوكن، captcha، إرسال OTP، التحقق منه، رفع الصورة، وتحول الحالة إلى pending.
- فحص نحوي لجافاسكربت الصفحة المرفقة بعد التنظيف.
